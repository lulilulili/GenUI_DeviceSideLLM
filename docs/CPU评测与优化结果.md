# CPU 评测与优化记录

本轮使用本机 Ollama qwen2.5:3b。全部 63 条均已运行，多轮失败项回归已完成。

## 可核实的结果

最后一次完整运行 `evals/results/qwen2.5-3b-final-63.jsonl`：

- 62/63 条全部关键断言通过，453/458 个断言通过。
- P50 11.708 秒，按评测器现有分位数算法 P95 20.209 秒。
- 累计请求时间 797.096 秒，约 13.3 分钟。
- 唯一失败为 device_multi_01：手机电量规则覆盖了多任务中的蓝牙与耳机。

该规则已限制到非耳机的单任务查询。随后 `scope-fix-check.jsonl` 中 device_multi_01、device_headphone_01、noise_01 三条全部通过（18/18 断言）。因此 63 条现有用例均取得过通过结果；最后修复后未重新完整跑 63 条，不能将两份结果描述成同一次全量 100%。

## 速度变化和 Prompt

旧完整 RawIntentSpec 单条查询约 78.45 秒；精简协议最初约 36.3 秒。当前完整集 P50 约 11.7 秒。不同输入、缓存和运行状态均影响延迟，不能将两者直接作为严格控制变量的加速比。

当前生产入口为 `genui_intent/compact.py`，固定系统提示词为 371 个字符（不是 tokenizer token 数）。模型输出 tasks，参数和上下文使用稀疏对象，代码扩展为 RawIntentSpec v1.0。旧 prompts.py 保留，但不是当前默认生产提示词。

主要优化：减少输出中的固定字段与重复元数据；使用按领域收窄的 Schema；给候选加简短语义说明；查询与控制、单位、极值等由规则辅助规范化。API 仍输出完整协议。

## 成绩的限制

以上是模型加规则后的系统关键断言通过率，不是裸模型准确率，也不是完整 JSON 的语义正确率。大量规则是在这 63 条上开发的，这组数据应视为开发回归集，不能再充当独立测试集。

测试数据有两处口径变化：考试事件不再强制开放文本写成英文 exam；无上下文的“把它关掉”补充为智能家居控制页场景。后者属于用例修改，原来的无领域指代仍需要独立测试。

未覆盖字段仍出现过多余参数、上下文来源错误、任务删减后的自依赖。Schema 合法不等于可以执行动作。当前代码只适合意图研究，不应把 RESOLVED 直接作为执行授权。

## 进一步优化优先级

1. 保存首轮原始模型 JSON、后处理 JSON、每次调用的输入/输出 token、prefill/decode 耗时和重试原因。当前结果文件主要保存最终输出，无法计算规则真实贡献。
2. 建立未参与调参的新测试集，覆盖相反操作、不同数值、否定、跨域、多设备以及不支持请求；冻结后再测。
3. 缩小规则作用范围，特别是跨任务实体覆盖、时间传播和意图默认值；增强完整语义校验。
4. 拆分冷启动、热请求和有无重试性能。自我纠正用例仍约 60 秒，应通过原始输出确认截断/重试原因，再决定是否调输出预算。
5. 再比较更短字段名、按领域固定结构与线程设置。当前缺少硬件和 token 统计，不应直接承诺 CPU 可达到某个秒数。

逐条调试适合复现错误；主要调参应按失败类型处理，并回归受影响领域。每次只针对一条加关键词容易过拟合，本轮结果已经显示了这种风险。
