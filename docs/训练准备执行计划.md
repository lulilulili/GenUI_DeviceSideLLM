## 阶段 1 · 评测地基（≈1 周，先于一切训练）

| # | 步骤 | 具体动作 | 完成标准 | 向我汇报 |
|---|---|---|---|---|
| 1.1 | 冻结测试集 v1 | 按 `evals/frozen/README.md` 的 8 桶写 300~500 条（每桶 40~60）。流程：每桶先人工写 10 条 → 云端大模型仿写扩充 → **逐条人审**（改到你愿意签字为止）→ 存 `evals/frozen/frozen_set_v1.jsonl`（去掉 status 字段）。**只许纯自然语言**（实习生 84% vs 2/20 的教训） | 分桶数量达标；`run_frozen_eval.py --provider mock` 能加载不报错（它会校验每个期望键真实存在） | 分桶统计表 + 每桶 2 条样例 |
| 1.2 ✅ | harness 已建 | 熟悉一遍输出：`python evals/run_frozen_eval.py --dataset evals/frozen/frozen_set_template.jsonl --provider mock`，对照入门指南第五节理解每个指标 | 能说出 key_f1 / action_hallucination_rate / reject.false_bind_tokens 各是什么 | 无需汇报 |
| 1.3 | 裸模型基线 ×2 | `python evals/run_frozen_eval.py --dataset evals/frozen/frozen_set_v1.jsonl --model qwen2.5:3b --output evals/results/frozen-qwen3b-zero.json`，再用 `qwen2.5:1.5b` 跑一遍 | 两组完整报告 | 两组总表 + 分桶表 |
| 1.4 新增 | 检索 few-shot 基线 | 实习生的最反直觉发现：基座+同场景示例在"该不该做"的判断上（92%）远胜微调（≤56%）。做法：给每条用例按其领域检索一条**人工写的同域完整示例**（示例事实必须与用例明显不同，防他踩过的"示例事实污染"）拼进提示词，再跑 1.3 同款评测。第一版可以就按领域取固定示例，不用做向量检索 | 第三组报告 | **三组分数对照 → 决策点 A** |

**决策点 A（拿 1.3/1.4 结果来）**：
- 语素 key_f1 ≥85%（任一配置）→ 训练缓行，优先做厚注册表/变体，把 1.4 的检索方案工程化；
- 70~85% → 走 LoRA（阶段 2-3），1.4 结果决定训练目标里要不要保留检索示例；
- <70% → 带分桶明细回来，先定位是候选注入没生效还是任务本身难，再谈造数据。
- 先验参考：实习生同构任务**无候选注入**时裸 3B 严格 F1 仅 39%。我们有候选键
  注入，理应显著高于此；若没有，优先查注入机制而不是怪模型。

## 阶段 2 · 数据工厂（≈1-2 周）

| # | 步骤 | 具体动作 | 完成标准 | 向我汇报 |
|---|---|---|---|---|
| 2.1 | 骨架→query 反写（主力） | ① `python tools/gen_training_data.py enumerate`（125 骨架已验证）；② 把每行 `query_writing_prompt` 发给云端大模型，回收为 `data/factory/queries.jsonl`；③ **每个骨架抽 2 条人审**（重点：query 里说的和骨架字段是否一致）；④ `python tools/gen_training_data.py expand --queries data/factory/queries.jsonl` | 第一层 3k~8k 条；audit 清单齐全 | 数据分布统计 + 20 条抽样 |
| 2.2 ⚡ | 蒸馏 + 拒绝采样 | 云模型跑生产 prompt 出语素草稿，过 `protocol.validate_draft` + 绑定检查：通过→SFT 集；被拒→(prompt, 坏输出, 好输出) 偏好对存 `dpo_pairs.jsonl` | 拒绝率有记录 | 通过率 + 被拒原因 Top5 |
| 2.3 | 修复轨迹样本 | (原 prompt + 错误输出 + 校验错误 → 修正输出) 多轮样本 500~1k 条；来源：2.2 被拒样本 + 人造典型错误 | 覆盖 Top5 错误类型 | 错误类型覆盖表 |
| 2.4 | 成对边界样本（升级） | 每类边界都构造**最小对**（同场景一正一负）：该拒 vs 该做（unsupported 相邻场景）、字段超纲 vs 字段存在、该加动作 vs 不该加动作。各 100~300 条。SFT 教不会"不做什么"（实习生：负例准确率微调后反降 12 点），所以负样本同时进 2.2 的偏好对留给 DPO | 四类齐、正负配平 | 各类数量 |
| 2.5 | 组装与切分 | 合并去重 → **按场景语义切分** train/val → `python tools/check_leakage.py --train <train文件> --frozen evals/frozen/frozen_set_v1.jsonl --strict-keyset`。冻结集及其改写变体绝不进入；数据卡记录 `prompt-manifest.json` 的契约版本 | 泄漏检查通过（strict 模式） | 数据卡（总量/配比/切分/契约版本） |
| 2.6 新增 | 渲染质量门 | 全量 target 草稿过完整管线出卡（不调模型，直接从 expand_draft 进）：`PYTHONPATH=. python -` 脚本遍历 target_draft → 管线 → 无异常且有 HTML 输出。实习生对 5000 条全过真实渲染、0 失败——比 schema 校验多拦一层"合法但渲染出错" | 0 失败或逐条修完 | 失败数与原因 |

## 阶段 3 · 训练与验收（≈1 周）

| # | 步骤 | 具体动作 | 完成标准 | 向我汇报 |
|---|---|---|---|---|
| 3.1 | LoRA SFT | qwen2.5-3b（决策 A 若倾向 1.5b 则两个都训）。起点参数直接抄实习生验证过的：QLoRA 4-bit NF4，r=16 / alpha=32 / dropout=0.05，全部线性层，**answer-only loss**，2~3 epoch。先用 300 条小样跑通流程再上全量 | val loss 收敛无回升 | 训练曲线 + val 指标 |
| 3.2 | 冻结集复测 | 训后模型跑 harness，**必须带记忆切片**：`--train-file <train文件>`。与 1.3/1.4 三组基线同表对比；重点看 seen/unseen 两组分差（>10 点 = 记忆水分，回查 2.5） | 对照表完整 | **四组对照表 + 记忆切片 → 决策点 B** |
| 3.3 | 量化验收 | 合并导出 GGUF Q4_K_M，进 Ollama（Modelfile），**量化版再跑冻结集** | 量化回退 ≤3 点 | 量化前后分数差 |

**决策点 B（拿 3.2/3.3 结果来）**：达标 → 阶段 4；一次通过率仍低但 F1 高 →
用 2.2/2.4 偏好对做 DPO 一轮再测；负例指标（拒绝类、动作幻觉）不达标 →
这正是 SFT 的已知盲区，直接走 DPO 而不是加 SFT 数据；整体不达标 → 带错误
分类表回来定位。

## 阶段 5 ·（前瞻）盘古 3B / 昇腾迁移检查单

到手盘古后按此清单走，凡是"资产"级的东西一件不换：

1. 冻结集、harness、泄漏检查、数据工厂、契约清单 → **原样复用**；
2. SFT 数据 → 内容不变，按盘古 chat template 重新包装 messages；
3. 重跑 1.3 裸模型基线（决策 A 重新走一遍——盘古的分数分布可能完全不同）；
4. 训练脚本 → 按当时官方文档选 MindFormers 或 torch_npu 路线（CANN 是底层
   算力栈，你不直接操作它）；
5. tokenizer 变了 → 重核提示词 token 长度与延迟账；
6. 量化路线换昇腾端侧格式 → 军规不变：量化后必复测冻结集。
