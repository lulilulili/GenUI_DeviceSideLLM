# GD 训练数据集设计说明（v1）

> 交付物：`data/factory/sft_train_v1.jsonl`（messages 三元组，可直接微调）
> 配套：`sft_train_v1.audit.jsonl`（逐行审计）；泄漏检查报告
> 契约版本：`evals/prompt-manifest.json`（morpheme-v2-2026-09-11）

## 1. 训练目标

单次调用：用户中文话语 → 4 字段语素草稿 `{"t","m":[{"l","q","f","r"}]}`。
组件/布局/绑定/数据全部由确定性代码决定，模型只学"语义坍缩"。
训练样本**逐字节复刻生产提示词**（含按领域候选键注入，`protocol.build_messages`）——
这是与实习生工作的关键差异之一：他无候选注入时裸 3B 严格 F1 仅 39%。

## 2. 数据来源（参考 CC 的枚举思路 + 借实习生的方法论教训）

- **骨架（=答案）**：`tools/gen_training_data.py enumerate` 从能力注册表反向枚举
  125 个合法语素组合（主语素 × ≤2 辅助 × 可选动作 + 纯开关卡），
  覆盖率由枚举保证——这是从 CC gallery"合法空间可穷举"思路借来的；
- **query（=问题）**：工作流按每骨架 12 条反写（口语一半、2 省略、2 错别字、
  1 长句、1 间接表达），审校代理过滤越界后落分片；
- **风格扩增**：`expand --styles-per-query 2` 确定性风格轴（借实习生 8 风格思路），
  只动表达不动语义；
- **从实习生借的防线**（已固化为工具）：审计与样本分离（audit manifest）、
  契约版本绑定、三层泄漏检查（check_leakage.py）、纯自然语言红线。
- **不使用**：实习生的 runtime_context 与 target_frame（契约不同）；
  intern_used_seed_ids 对应措辞（已进冻结集，训练侧永久排除）。

## 3. 生成管线（全自动，可复跑）

```text
gen_training_data.py enumerate → 125 骨架（含 query 反写指令）
Workflow：生成代理(按骨架指令写 12 条) → 审校代理(删越界/非自然/近重复，写分片)
合并分片 → queries.jsonl → gen_training_data.py expand（风格×2 + 生产提示词渲染）
→ check_leakage.py --train sft_train_v1.jsonl --frozen frozen_set_v1.jsonl（三层必过）
```

## 4. 标签推导（LLM 零参与）

骨架的 target_draft 即 assistant 标签：l 取注册表最短中文别名、q 即语义键、
f 即注册表 valueType、r 按 主=PRIMARY / 第一辅=SECONDARY / 其余=SUPPORTING /
开关=PRIMARY_ACTION 固定规则。角色规范化/组件推导等下游行为不进标签——
它们是运行时代码的职责。

## 5. 泄漏防线

1. 冻结集（含 58 条 unsupported + 后续各桶）及其改写变体绝不进训练——
   `check_leakage.py` 文本级/近重复/事实级三层检查为组装后必跑步骤；
2. 实习生种子衍生措辞（intern_used_seed_ids）训练侧全量排除；
3. 归一化去重；审计记录骨架 ID/风格/行号。

## 7. 微调建议

- answer-only loss；LoRA/QLoRA r=16 α=32 dropout=0.05 全线性层
  （实习生验证过的起点），2~3 epoch，先 300 条小样跑通再上全量；
- 评测：`evals/run_frozen_eval.py --train-file <本数据集>`（自动做记忆切片：
  seen/unseen 分差 >10pt 即记忆水分回查切分）；
- 决策点 A/B 流程见 `docs/训练准备执行计划.md`。

## 8. 已知边界（诚实声明）

- 本集只教"该做什么"；"不该做什么"（拒绝/假绑）SFT 教不会
  （实习生实测负例准确率微调后反降 12pt）——按计划 2.4 留给成对边界样本 + DPO；
- 反写 query 与真实用户分布的差距要靠冻结集把关，不能用训练分数自证；
- CONTENT 域 generator 条目未入骨架（内容模块未接）。
