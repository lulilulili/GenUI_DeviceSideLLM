## 一、全局流程图

```text
用户话语 + 尺寸/风格偏好
   │
   ▼
① 领域路由（确定性：注册表别名派生词表；未命中→12-token 模型路由兜底）
   │
   ▼
② 语素草稿【唯一一次主 LLM 调用】
   {t 标题, m:[{l 标签, q 语义键, f 数据形态, r 信息角色}]}
   约束解码(JSON Schema) + 结构校验 + ≤1 次带错重试
   │
   ▼
③ 角色规范化（多 PRIMARY 自动降级 / 缺 PRIMARY 自动提升 / 动作>2 降级；零重试成本）
   │
   ▼
④ 能力绑定（EXACT→ALIAS→TOKENS 三级解析→跨域营救→MISS；
   命中即获得 数据路径/动作/权限/首帧值，注册表 valueType 覆盖模型猜测）
   │
   ▼
⑤ MISS 分级处置（无绑定动作删除 / 无绑定辅助删除 / 主信息保留静态文本）
   │
   ▼
⑥ 业务变体层*（PRIMARY 绑定键命中变体 primaryData → 补 curated 辅助字段，主焦点切换）
   │
   ▼
⑦ 组件推导（纯查表：(r,f) → TEXT/METRIC/STATUS/PROGRESS/SWITCH/SLIDER/BUTTON/LIST）
   │
   ▼
⑧ 注册表联想补充*（预算有余时补同 Provider 姊妹条目；变体命中则让位；
   绝不补 BOOLEAN 控件；布局落自由模式时自动回退保模板命中）
   │
   ▼
⑨ 同类聚合（按钮超容量→横滑 chips 操作条；METRIC/STATUS 溢出→保最高优+折叠列表行）
   │
   ▼
⑩ 尺寸决策 + 信息预算（AUTO 按组件成本定尺寸；按优先级裁剪到预算内）
⑪ 层级预算*（每尺寸限信息层级数与列表可见行数）
   │
   ▼
⑫ 标签消隐（同类唯一 × 值自明 × 标题覆盖 → 隐藏冗余标签，保留为 a11y 标签）
   │
   ▼
⑬ 布局
   18 个 PDF 原型评分匹配（EXACT>FAMILY>FOOTPRINT + 角色加分 + 近优稳定选型）
   ├─ 放不下 PRIMARY 的原型直接出局；低优先放不下→省略保命中；高优先放不下→
   └─ 层级式自由布局（主视觉带→细节网格→底部操作条；几何感知打包：
      最小像素高度分带 + 前瞻预留 + hero 收缩 + 标题栏让位于内容）
   两模式共用几何提示后处理（短槽环形→紧凑数字、局促格子→紧凑字号档）
   │
   ▼
⑭ 设计令牌渲染 → HTML 预览 / 标准 A2UI 三段 / 极简 DSL

（* = 可插拔适配层，features 开关，全关时链路与引入前一致）
```

模型调用总量：常规 1 次（+路由兜底 12 token / +纠错重试各最多 1 次）。
其余 13 步全部确定性，可单测、可回放、可解释。

## 二、每一步的设计考量

| 步骤 | 设计考量（为什么这么设计） |
|---|---|
| ①路由 | 词表由注册表 aliases **派生**而非手写——单一事实来源，注册表扩容路由自动跟上；先规则后模型，多数请求零 token |
| ②语素草稿 | **模型只做语义坍缩**：把无穷措辞坍缩到 4 个受约束字段。所有 3B 做不稳的事（组件/布局/绑定/数据/视觉）都不在这次调用里。固定前缀+动态尾部→KV 缓存复用（实测 prefill 971→429ms） |
| ③规范化 | **能被代码修的错不许消耗模型重试**。"恰好 1 个 PRIMARY"在提示词里是引导、在代码里是修复，不是失败条件 |
| ④绑定 | **模型输出是线索不是地址**。q 只用于查表，表外键绝不执行；中文标签是第二证据通道，中英映射的重担压在注册表词库而非模型翻译 |
| ⑤MISS 处置 | 按信息价值分流：死按钮比空白更糟（删），填不上的填充物不占位（删），用户点名要的宁可降级展示（留） |
| ⑥变体层 | 借鉴 CreateMyCard primaryData："主数据不同即不同模板"。主焦点切换靠查表不靠碰运气；对模型零负载 |
| ⑦组件推导 | **一个决策一个 owner**。v1 让模型选组件再用规则纠正=两个 owner 且过拟合；v2 组件由 (r,f) 完全推导，错误类整体消失 |
| ⑧联想补充 | 丰度问题的答案是**注册表联想而非模型联想**——模型联想会编造，注册表只会补真值。优先级压最低，永远给用户内容让位 |
| ⑨同类聚合 | 溢出不裁剪而是**换容器**：10 个按钮坍缩为横滑 chips，每项保留动作；容器属 COLLECTION 族反而更易命中原型 |
| ⑩⑪预算 | 成本预算管"塞不塞得下"，层级预算管"看不看得懂"（1-2 秒读卡原则的数据化） |
| ⑫消隐 | 标签隐藏的判据是"与其他信息通道冗余"，可计算；视觉隐藏≠信息删除（保 a11y） |
| ⑬布局 | 原型优先（设计师权威），自由兜底（永不失败）；**内容 > 模板 > chrome** 的取舍链——放不下时先弃原型、再弃标题栏、最后才弃低优先内容 |
| ⑭渲染 | 模板只声明结构，视觉全走令牌——换主题/深色只动 tokens.py |

贯穿全局的五条不变量：
1. 模型输出只是候选决策，永远不能绕过注册表与校验器；
2. 一个决策恰好一个 owner；
3. 可代码修复的错误就地修复，不消耗模型重试、不失败；
4. 失败模式限定在安全侧（最坏=少显示一条/不够好看，绝不绑错数据、执行错动作）；
5. 规模增长（能力/模板/主题/变体）全部落在确定性侧，模型接口规模不变。

## 三、LLM 如何准确提取关键语义

准确性不是靠一段聪明的提示词，而是**四层机制的乘积**，按贡献排序：

1. **把抽取变成选择**（贡献最大）：路由确定领域后，该领域的语义键候选全部注入
   提示词（≤24 个）。"待办"→从 5 个键里挑 `task.list` 是嵌入级近邻任务，3B 稳定
   胜任；实测天气/待办场景模型输出与注入候选逐字符一致（EXACT 率 100%）。
   近义词（"备忘的事项""明天的安排"）同样被坍缩到规范键——**LLM 本身就是这条
   链路里的近义词引擎**，这是保留它的理由。
2. **few-shot 定格式**：一条例子同时演示字段、角色分布（1 PRIMARY+辅+ACTION）和
   键风格，对小模型比十条指令有效；候选没覆盖时模型按例子风格仿写英文键。
3. **约束解码 + 纠错闭环**：JSON Schema 约束让结构合法率≈100%；确定性校验失败时
   带具体错误重试一次（实测：3 个 PRIMARY 被拒→重试把 PRIMARY 正确落在"是否会
   下雨"上——纠错不只修格式，还会修语义重心）。
4. **宽容的下游**：三级解析 + 中文标签双通道，模型的模糊输出被注册表词库接住；
   接不住的安全降级。模型不需要完美，只需要"大致对"。

### 各语义字段展开后如何生效

| 字段 | 下游消费点（生效链） |
|---|---|
| `q` 语义键 | ④绑定查表→数据路径/动作/权限/首帧值/刷新方式；⑥变体选择的键；消隐的图标推断 |
| `f` 数据形态 | ⑦组件推导主输入（PERCENTAGE→环、BOOLEAN+ACTION→开关）；绑定成功后被注册表声明**覆盖自愈**——模型猜错形态零成本纠正 |
| `r` 信息角色 | ③规范化对象；优先级（预算/降级顺序）；⑬槽位匹配（角色词表=原型槽位词表）；自由布局分带（主带/细节/操作条）；⑤MISS 处置分流；视觉强调 |
| `l` 标签 | 展示文本（模型唯一自由文本，承载本地化）；④解析的第二证据；⑫消隐判断输入；隐藏后的 a11y 标签；MISS 时的安全兜底展示 |
| `t` 标题 | 自由布局标题栏；⑫消隐的上下文覆盖判据；近优模板稳定选型的签名输入 |

## 四、当前流程的问题（诚实清单）

1. **语义准确率未经冻结集测量**——最大未知数。所有准确率数字目前是机制推断+
   零散真机验证，v1 的教训（开发集 98% 注水）必须避免重演。
2. **延迟未达产品级**：桌面 CPU 单次 8~12s；NPU 3~6s 是纸面推算未实测。
3. **注册表规模化三连**：候选注入随能力数膨胀（需提示词前置确定性预检索）；
   别名词表维护成本线性涨（需离线挖掘管线）；长尾近义词漏网（需嵌入检索第 4 级）。
4. **数据是演示态**：绑定插的是 sampleValue，真实数据通道、运行时刷新（PULL/PUSH
   已声明未实现）、权限门禁流程都是空位。
5. **CONTENT 域是占位**：generator 条目返回样本文案，内容生成模块未接。
6. **密集构成命中率**：STATUS 主焦点天气这类组合走自由布局——缺对应业务变体
   模板，靠放宽匹配阈值解决是错误方向。
7. **渲染是近似**：HTML 预览≠真机 A2UI 渲染；横滑 chips 的手势能力需真机确认，
   不行则退化为"前 N + 更多"。
8. **单轮单域**："天气加日程放一张卡"的多域组合、多轮编辑均未支持。
9. **评测覆盖不对称**：68 用例只测布局层（确定性），模型层端到端评测集为零。

## 五、改进建议（按优先级）

1. **冻结测试集**（300~500 条：否定/跨域/长尾措辞/不支持请求），测裸模型语素
   准确率——这个数字决定 3B 直用 / 1.5B+LoRA / 4B 三条路线的选择；
2. **NPU 真机延迟实测**（一台样机一天）；
3. **注册表工业化**：从云侧 data/event_capabilities.json 自动派生条目 + 别名离线
   挖掘（大模型批量生成同义词）+ MISS 日志回流 + 嵌入检索第 4 级解析；
4. **语素级多轮编辑**：旧 morphemeSpec + 指令 → 模型输出语素 diff，链路其余复用
   ——比 DSL 层编辑对 3B 友好一个量级，是本架构的天然优势；
5. **真实数据绑定与权限流**（对接系统能力，替换 sampleValue）；
6. **高频域业务变体模板扩充**（对照 68 用例中的自由布局案例逐个补）；
7. **金样快照回归**（68 用例渲染结果快照 + diff，锁住视觉质量）；
8. **LoRA 数据工厂**（注册表枚举全部合法输出 × 反向生成多样 query，冻结集不达标
   时的升级路径，标注零成本）。

## 六、项目价值

**技术价值：验证了"3B 端侧模型驱动生成式 UI"的可行分工范式。**
行业共识是小模型直接生成 UI（DSL/HTML/组件树）不可靠；本项目证明换一种切法可行
——模型只负责把自然语言坍缩成 4 字段语义（它唯一擅长且不可替代的事），UI 的
正确性、美观、安全全部由确定性层保证。配套产出：可复用的语素协议、声明式能力
注册表（即系统 API 注册形态答案）、几何感知布局引擎、全链路可观测工作台、68 例
布局回归集。与云侧 CreateMyCard 是同一哲学的两端实现，资产可互相派生。

**端侧化的独立价值**：隐私（数据与意图不出设备）、离线可用、零云端推理成本、
（NPU 后）低延迟、以及"能力注册表=生态接入点"的平台潜力。

## 七、商业落地场景

| 场景 | 为什么匹配 | 备注 |
|---|---|---|
| **手机桌面卡片 / 负一屏**（最直接） | 对标 CreateMyCard 的端侧化：说一句话生成个性化服务卡，零云成本、隐私合规、离线可用 | 厂商 OS 差异化卖点；注册表=第三方 App 接入生态（类小程序卡片） |
| **智能座舱** | 语音→仪表/中控临时卡片；车机离线刚需、延迟敏感、安全要求高——确定性层"绝不执行表外动作"天然匹配车规思路 | 组件受限环境正好用模板族 |
| **IoT 中控屏 / 全屋智能面板** | "把客厅设备放一屏"→SWITCH/SLIDER/聚合 chips 正是为此设计；设备清单天然是能力注册表 | 家庭隐私敏感场景 |
| **穿戴/手表卡片** | 极小画布+严格信息预算——层级预算/降级/消隐机制在小屏价值放大 | 1.5B 档模型即可 |
| **金融/政务等私有化 App** | 数据不出端/不出域的合规硬约束下做个性化服务入口，云端方案直接出局 | 端侧是唯一解，不是备选 |
| **适老化/无障碍** | 语音生成大字卡；语素层自带 a11y 标签，消隐不丢读屏信息 | 政策驱动的确定需求 |

商业模式候选：厂商预装授权（OS 功能）、能力注册表生态分成（Provider 接入）、
行业私有化交付（座舱/金融）。共同的护城河不是模型（会被追平），而是
**注册表资产 + 模板/变体库 + 确定性质量层**——这些随接入方数量复利增长。
